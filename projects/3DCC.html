Overview

This project is a Vulkan renderer I built from scratch over seven labs. It starts with drawing points and lines and ends with a PBR renderer that loads glTF models, textures, and environment lighting. Each lab built directly on the last, so the final project is one renderer that grew step by step.

  • Custom vertex formats, shaders, and multiple graphics pipelines
  • Uniform buffers, storage buffers, and descriptor sets for sending data to the GPU
  • Free-look 3D camera with keyboard, mouse, and controller support
  • OBJ and glTF model loading, with instancing and per-mesh materials
  • Bindless texture arrays, normal maps, and emissive maps
  • PBR shading with image-based lighting (IBL)

What I Worked On

Pipelines, Shaders & Vertex Data (Lab 1)

I started by drawing 10,000 random stars as points, then added a second pipeline to draw a connected-line star on top.

  • Pipeline Topology — The pipeline decides how vertices are drawn (points, lines, or triangles), so each shape type needs its own pipeline.
  • Custom Vertex Type — I added RGBA color to the vertex, then wrote new vertex and fragment shaders to match.
  • Rule of Three — The C++ vertex struct, the Vulkan attribute descriptions, and the shader input all have to agree, or nothing draws correctly.

Almost every “nothing is drawing” bug I hit came from one of those three being out of sync.

Sending Data to the GPU (Labs 2–3)

I rotated a “+” shape with push constants, then moved to uniform buffers and descriptor sets once I needed more than 128 bytes.

  • Push Constants vs. Uniform Buffers — Push constants are quick but limited to about 128 bytes. Uniform buffers hold much more but need a descriptor set layout, pool, and set.
  • Per-Frame Buffers — I made one uniform buffer and one descriptor set per in-flight frame, so the CPU never overwrites data the GPU is still reading.
  • Indexed Geometry & Instancing — Index buffers let triangles reuse vertices. I drew all six walls of a room with one instanced draw call, using SV_InstanceID to pick each wall’s matrix.

Vulkan doesn’t synchronize CPU and GPU data for you, so per-frame buffers are what prevent flicker.

3D Math & Camera (Lab 3)

I built a procedural 3D grid room, then added world, view, and projection matrices and a free-look camera.

  • Vulkan Projection — Vulkan’s NDC has Y pointing down, so I had to either use a Vulkan-style projection or turn off the shader compiler’s Y-flip, not both.
  • Matrix Layout — HLSL reads matrices as column-major while most math libraries use row-major, which breaks the math unless you account for it.
  • FPS Camera — Movement is relative to where the camera faces. Strafing and forward motion use local translation, and yaw uses global rotation to stay FPS-style.

Keeping the camera as a world matrix and inverting it for the view matrix made the movement code far simpler.

Model Loading & Lighting (Lab 4)

I loaded the FSLogo OBJ model, then added a directional light with ambient and specular.

  • Model Data — I converted the OBJ and its materials into a header, then fed the vertex and index data through the rule of three.
  • Per-Mesh Instance Data — A storage buffer (StructuredBuffer in HLSL) holds a world matrix and material for each mesh, so the draw list doesn’t need hard-coded sizes.
  • Lighting — Lambert diffuse, an ambient term, and specular that depends on the camera position.
  • Debugging with RenderDoc — I used it to confirm geometry was loaded and to step through individual pixels.

Interpolated normals need re-normalizing in the fragment shader, and the instance index needs nointerpolation so it doesn’t get blended across a triangle.

glTF Loading (Lab 5)

I upgraded from OBJ to glTF using TinyGLTF, then rendered a high-poly model with the lighting from Lab 4.

  • Unified Buffer — glTF stores vertices and indices in one block of memory, so I used a single Vulkan buffer flagged as both vertex and index.
  • Offsets & Strides — Attributes are stored separately (non-interleaved), so I read each offset, stride, and index format from the model data instead of hard-coding them.
  • Blender Exporter — I used a custom exporter to make every model’s vertex format consistent, so I didn’t need branching load code.

Reading everything from the model data instead of hard-coding it is what let new models load without code changes.

Textures & Bindless Resources (Lab 6)

I loaded the model’s textures onto the GPU and used them in the lighting.

  • Separate Texture Descriptor Set — Textures never change between frames, so they got their own descriptor set instead of sharing the per-frame one.
  • Bindless Texture Array — I enabled the descriptor indexing extension so all textures live in one array that shaders can access freely.
  • Roughness & Ambient Occlusion — Roughness dampens specular highlights and occlusion reduces ambient light in crevices, which added visible depth.

Bindless textures took more setup, but adding a texture later became as simple as adding it to an array.

Advanced Rendering: Normal Maps & PBR (Lab 7)

In the final lab I fixed coordinate systems, improved depth precision, and added normal maps, emissive maps, and PBR with IBL.

  • Handedness — glTF is right-handed and my renderer was left-handed, so I flipped the model with a -Z world matrix and switched the front-face winding.
  • Reversed-Z — Clearing depth to 0 and using a GREATER compare gives far better precision at extreme near and far planes.
  • Normal & Emissive Maps — A TBN matrix converts each pixel’s normal from the map into world space, and I flipped the green channel because glTF uses OpenGL-style normal maps. The emissive map just adds glow on top.
  • PBR + IBL — I loaded a GGX lookup table and diffuse and specular cube maps, then switched to a PBR fragment shader.

Depth, handedness, and normal map conventions all caused bugs that looked like “lighting is wrong,” so I learned to check the coordinate conventions first.

Notes

Rendering Overview

Every frame, the CPU updates the camera, lights, and per-instance data. Those go into per-frame uniform and storage buffers, which descriptor sets expose to the shaders. The vertex shader transforms geometry into world space, and the fragment shader applies materials, textures, and lighting.

  • Static resources (textures, environment maps) are separate from per-frame resources (camera, instance data)
  • Validation layer output and RenderDoc captures were my main debugging tools
  • Buffer offsets, strides, and counts come from the model data, never hard-coded

Lessons Learned

  • The rule of three (C++ data, Vulkan descriptions, shader input) is the first thing to check when nothing draws
  • Vulkan doesn’t synchronize frame data for you, so use one buffer per in-flight frame
  • Coordinate conventions (handedness, NDC Y direction, matrix order, normal map style) cause bugs that look like lighting problems
  • RenderDoc and the validation layers find problems much faster than guessing
