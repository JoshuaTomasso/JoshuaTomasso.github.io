Overview

This project involved setting up a virtual machine with Ubuntu, running a server, and developing a game in Unreal Engine 5 using JetBrains Rider.

  • Dual Boot Setup with Windows and Ubuntu
  • Ran a Palworld Server for the Terminal
  • Build and Played a personal project in Unreal Engine 5
  • Ran A Windows Virtual Machine with Ubuntu
  • Linked a file to the Virtual Machine between the Linux OS and the Windows OS

What I Worked On

Setup and Ran a Palworld Server

Used the terminal to set up and run a Palworld server.

  • DOCKER — Using Docker to containerize the Palworld server, making it easy to deploy and manage across different environments.
  • Testing — I was able to launch the server and test its functionality in Palworld.

Working through this taught me how server processes actually get deployed and managed on Linux, and gave me hands-on experience containerizing an application so it can run consistently regardless of environment.

Build and Ran A Personal Project in Unreal Engine 5

Was able to bring a personal project (Hidden Fangs) to life in Unreal Engine 5 running on a Linux operating system.

Getting Unreal Engine 5 fully operational on Ubuntu, including compiling and running the project through JetBrains Rider, showed me how game development workflows differ outside of Windows and gave me confidence troubleshooting engine and toolchain issues on Linux.

Windows Virtual Machine with Ubuntu

I used LXD (Canonical's system container and VM manager) to create and run the virtual machine

  • LXD — Used LXD to provision and manage a Windows virtual machine directly from the Ubuntu host, allowing me to run Windows-only tools alongside my native Linux environment.

This gave me practical experience with virtualization on Linux, letting me switch between operating systems without dual-booting or needing a second machine.

Linked a file between the Windows VM and the Linux host

I linked a file between the Windows VM and the Linux host. This is so I can share data between the two systems.

  • Shared Folder — Configured a shared directory between the Ubuntu host and the Windows VM so files could be moved between the two environments without needing external transfer tools.

This solved a real workflow problem: being able to pass files back and forth between the two OS environments made development and testing much faster and less disruptive.
