Unreal Engine 5 C++ UI Framework & Behavior Tree AI

Overview

Killshot Momentum is a first-person momentum game where the goal is to finish each map as fast as possible while enemies block key paths and level misdirections throw you off course. Reaching the end portal shows your completion time and lets you replay, advance, or return to the menu.

  • Six C++ UserWidget classes: a reusable button, main menu, pause menu, key bindings, HUD and results screen
  • Enemy AI with AIPerception, a Blackboard and two Behavior Tree variants
  • Game Instance–driven level flow: load first, current and next level, main menu, quit
  • Settings built on Game User Settings with a hardware benchmark

What I Worked On

C++ UI Framework

Every menu in the game shares one C++ button class, so behavior is written once and each screen only binds to it.

  • Reusable Button — UCodeButtonWithText uses meta = (BindWidget) to bind its Button and TextBlock to the widget blueprint, exposes a BlueprintAssignable OnClicked delegate, and sets its label in NativePreConstruct so the text shows in the editor preview.
  • Menus as Thin Classes — The main menu, pause menu, key bindings and results screen bind to that delegate with AddDynamic. Widget classes to open next are TSubclassOf properties set in Blueprint, so C++ never hard-references an asset path.
  • Direct Game Instance Binding — The main menu binds Play and Quit straight to UCodeGameInstance::LoadFirstLevel and QuitTheGame. Pause, results and menus all route level changes through the same Game Instance functions.
// CodeButtonWithText.h: bound to the widget blueprint, exposed to every menu
UPROPERTY(meta = (BindWidget)) class UButton* BackgroundButton;
UPROPERTY(meta = (BindWidget)) class UTextBlock* Information;
UPROPERTY(BlueprintAssignable, Category = "Button") FOnClickedEvent OnClicked;

// CodeMainMenu.cpp: menu buttons call Game Instance functions directly
GameInstanceObject = Cast<UCodeGameInstance>(UGameplayStatics::GetGameInstance(GetWorld()));
if (GameInstanceObject)
{
    PlayGame_Button->OnClicked.AddDynamic(GameInstanceObject, &UCodeGameInstance::LoadFirstLevel);
    QuitGame_Button->OnClicked.AddDynamic(GameInstanceObject, &UCodeGameInstance::QuitTheGame);
}

One button class means hover colors, click handling and label setup live in one place, and a new menu is just a layout plus a few bindings. Keeping level changes in the Game Instance means no widget ever calls OpenLevel itself.

Results Screen & Run Timer

UCodePlayerScore reads the finished run time from the Game Mode, formats it, and returns the player to the menu automatically if they walk away.

  • Time Formatting — The elapsed float is split into minutes, seconds and milliseconds with FloorToInt and Fmod, then zero-padded with FString::Printf.
  • Auto Return — SetWin hides the button area, switches a UWidgetSwitcher to the results page and starts a one-shot timer that calls LoadMainMenu.
int32 TotalMinutes      = FMath::FloorToInt(TotalTime / 60.0f);
int32 TotalSeconds      = FMath::FloorToInt(FMath::Fmod(TotalTime, 60.0f));
int32 TotalMilliseconds = FMath::FloorToInt((TotalTime - FMath::FloorToInt(TotalTime)) * 1000.0f);
FString Formatted = FString::Printf(TEXT("%02d:%02d.%03d"), TotalMinutes, TotalSeconds, TotalMilliseconds);

// SetWin(): return to the menu after a delay so the screen never gets stuck
GetWorld()->GetTimerManager().SetTimer(TimerHandle, this, &UCodePlayerScore::LoadMainMenu, TimeToMenu, false);

Enemy AI: Perception, Blackboard & Behavior Trees

Enemies that block the route have to react to the player without overcomplicating a speed-run. I built the AI Controller, the Blackboard and two Behavior Tree variants.

  • Perception to Blackboard — The AI Controller binds HandlePerception to AIPerception's On Target Perception Updated event. A successful stimulus writes the detected actor to the Player key and a lost one clears it. The tree only reads that key and never talks to perception directly.
  • Behavior Tree — A Sequence runs a custom BTTask_FaceObject task each cycle. The Blackboard holds SelfActor and Player.
  • Two Variants — BT_LookAtXYZ applies the full look-at rotation, so an enemy can tilt toward a player above or below it. BT_LookAtXZ only applies yaw by building the rotator from roll and pitch that already exist, so grounded enemies stay upright.

Choosing the rotation axes per enemy was a design decision, not a bug fix. Tilting a standing enemy toward a jumping player looks wrong, while a floating one should track in all axes. Splitting the task into two variants kept each one simple.

Settings & Game Flow

The settings menu uses Unreal's Game User Settings, so window mode, resolution, frame rate limit and the scalability options persist between sessions without custom save code.

  • Hardware Benchmark — An Optimal Settings button runs the Game User Settings benchmark and writes the recommended values back into every selector.
  • Menu Flow — Main menu, pause menu, key bindings, settings and results each swap to the next widget with the same create, add and remove pattern, so the flow is easy to extend.
